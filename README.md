# 大肥鱼的家

一个真 3D 的小房间。大肥鱼住在里面，自己决定干什么、自己走过去干；你在 QQ 上和她聊天，房间里的她会同步反应。

- **灵感来源**：B 站 UP 主「-止于言情--」的视频《[欢迎光临大肥鱼的家](https://www.bilibili.com/video/BV1GrxW6XEgN)》（BV1GrxW6XEgN）。
- **角色**：大肥鱼，设定与三视图来自暮之鸣（B 站 uid 38871361）。
- **她的「脑子」**：跑在 [DeepSeek Harness（DSH）](https://github.com/deepseek-ai/deepseek-harness) 里的 AI。房间只是她的身体，聊天、刷 B 站这些靠下面几个 DSH 插件（都是别的作者写的，本仓库不包含它们的代码）：
  - **QQ 聊天**：[dsh-onebot-qq](https://github.com/mario841859784/dsh-onebot)，OneBot 11 协议，配 [NapCat](https://github.com/NapNeko/NapCatQQ) 登录 QQ。
  - **刷 B 站**：[dsh-bili-whale](https://github.com/Alterssss/dsh-bili-whale)，她自己按作息刷 B 站、看视频、写日记，看到好的就在 QQ 上分享给你；分享的视频，房间里的她会跑去电脑前看。
  - **人设与记忆**：[dsh-soul-md](https://github.com/Scorp1o117/dsh-soul-md)。
  - **主动搭话**：[dsh-speak-up](https://github.com/Yuuyuko-uu/dsh-speak-up)，没人理她的时候她也会自己起个话头。

  怎么把它们和房间接起来，见下面「[和 DSH 及其他插件结合](#和-dsh-及其他插件结合)」。

和「播放几段固定动作视频」的做法不同，这里**没有任何预先录好的动画或视频**：房间、角色、每一个动作都是浏览器实时算出来的，镜头可以随便转。

## 她会做什么

- **自由活动**：按时间、天气、心情自己挑事做——溜达、坐床沿晃腿、躺着发呆、趴在床上刷手机、去窗边看雨（站在左右某一扇窗格前扒着窗、抱膝坐、斜坐托腮，待久了自己换姿势）、跳上椅子再跳上书桌玩电脑、去书架拿书窝在懒人垫上看、跳舞（两套随机挑：原来那套，和照着视频编的叉腰扭胯、转身、张开手臂左右晃那段）、练枪、打拳、踢球、给盆栽浇水、去小音箱那儿放歌、伸懒腰、躲到桌子底下、跑到屏幕跟前挥手。天黑了会去开台灯，深夜（1:00–7:24）会关音乐、关灯、上床睡觉。
- **真的在走路**：地板是带障碍的网格寻路，床、窗台、椅子、书桌是小平台，她靠跳来上下。去哪、怎么去都是当场规划的。
- **程序化动作**：走、跑、蹦跳、坐、跪坐、躺、趴、打字、挥手……都是按关节实时算的姿势再平滑过渡；头发、尾巴、呆毛、鱼鳍耳会跟着身体甩。眨眼、视线、表情、说话的嘴型也是实时画的。
- **东西都在手里或者放在哪儿，不会凭空出现、悬在半空**：手机、碗、勺子、书、水壶、被头都是跟着她的手走的；拿起来要走过去、弯腰伸手，放下要放到一个实实在在的台面上。
- **手机随手放**：用完就搁在身边——在电脑前就搁在笔记本旁边，在窗台上就搁在窗台上，斜着放也行；睡前才收到枕头边。QQ 来消息时它在哪儿就在哪儿亮屏、震动、冒一圈圈光，她过去（就在手边的话伸手）拿起来，屏幕变成真的聊天记录。趴着刷视频时，它斜靠在枕头上，她托着腮看。点一下手机，她就去刷手机。
- **表情**：会眨眼；睡觉时闭眼，开心时笑眯眼，困了半睁眼；说话时嘴一张一合，还有开口笑、惊讶、撅嘴等几种嘴型，害羞时脸更红。
- **练枪**：前墙根（水壶和小音箱之间）有个小枪架，竖着插着一杆红缨枪。她偶尔（白天）会去拿下来，到地毯上面朝你练一段：持枪立正点个头，然后中平枪、弓步扎枪（枪从前手里滑出去，人往前一送）、拦拿扎（枪尖画两个圈再扎）、下势低扎、劈枪、挑枪、蹲低原地转一圈横扫、端着枪蹦一下落地就扎，随机串起来，中间会把枪竖起来换到另一只手、朝另一边练；最后收势，把枪插回枪架。红缨会跟着枪甩。练到一半手机响了，她会先把枪横放在脚边的地上，回头再捡起来（天黑了就只收起来不练）。也可以按「练枪」、点一下那杆枪（或枪架），或在 QQ 里让她「练练枪」。
  视频里那种把枪在身边、头顶整圈抡起来的「舞花」做不了：她手短、举不过头，枪又比她高一大截，竖着抡会扎进地板、横着抡会穿过自己，所以换成了「人转一圈带着枪扫」。
- **打拳**：照着主人给的视频编的一套空击，在地毯上面朝你打：先侧身一拳亮个相，然后两只拳头护在下巴前、脚下一颠一颠，打几组组合拳（刺拳、直拳、左摆拳、右上勾拳，中间下潜躲闪一下），打累了垂着手喘口气，再来几组。她胳膊短，拳头只能伸出去一小截，所以每一拳都靠拧腰、送肩、往前探身把劲儿送出去。按「打拳」，或在 QQ 里让她「打套拳」；说「去锻炼会儿」的话，练枪、打拳随便挑一样。白天她也会自己去练。
- **到点吃饭**：右墙根有一块贴地的木托盘，上面是电饭煲和一只碗（她只有 65 厘米高，电饭煲放在桌上她够不着）。早 7–9 点、中午 11:30–13:30、晚上 18–20 点（按电脑的真实时间，只在「跟随现实」下生效），她会自己去按开盖子、端起碗、用勺子从锅里舀三勺饭、合上盖子，端到地毯上坐下一勺一勺吃完，再去旁边的洗碗盆拧开水龙头、用海绵把碗洗干净、放回托盘。每顿只吃一次；吃到一半被叫走，碗会先搁在地上，回头接着吃。快到点还没吃时电饭煲亮红灯、冒热气。也可以按「吃饭」、点一下电饭煲，或在 QQ 里叫她吃饭。
- **睡觉自己盖被子**：被子是一整块布，平时堆在床尾。睡觉时她走到床尾弯腰抓住被头，倒退着把被子拖到床头，躺下后拉到下巴，身体把被子顶起来；醒来掀开，被子滑回床尾重新堆起褶子。枕头会被头压下去一点。
- **看你分享的 B 站视频**：你在 QQ 里发 B 站视频链接（或分享卡片），聊完她会去电脑前看，笔记本屏幕上显示这个视频的封面、标题、UP 主和播放进度（不是真的在播，画面是封面）。标题和封面是房间服务直接向 B 站公开接口查的，不经过她的 AI，不花 token。
- **心里话**：她的（独白：……）会以云朵气泡冒在头顶，只在房间里显示，不进 QQ（需要她的 AI 把独白发给房间，见「让她的意识直接控制身体」）。
- **拍照**：按「拍照」或者在 QQ 里让她拍，照片存到 `photos/`，并发到你的 QQ。她会听拍什么：「来张自拍」就举起手机自拍；「拍下窗外的风景」「拍一下盆栽」「拍张你的房间」就拿着手机走过去，横着端在胸前对准它拍（照片是从她手机的位置拍出来的）；「拍张你的米饭」——碗里有饭就拍那碗，碗是空的就先盛一碗搁在托盘上，拍完端起来吃掉。
- **放歌**：前墙根有个小音箱。她去按一下，就让这台 Mac 自带的「音乐」App 放 `大肥鱼的歌单`（歌单名在 `config.json` 的 `music.playlist` 里改）；音箱会跟着鼓动、冒音符，顶部显示正在放的歌。她偶尔会自己去放，听个十几二十分钟再关；睡前会关掉。
- **声音**：点底部的「声音」按钮打开（浏览器规定要先点一下才能出声）。有雨声、脚步、敲键盘、踢球、手机提示音和震动、电饭煲开盖、水龙头、翻书、勺子碰碗、快门等。都是浏览器现合成的，偏「示意」；想换成真录音，把文件按 `public/src/sound.js` 开头列的名字（如 `rain.mp3`、`step.mp3`）放进 `public/assets/sfx/` 即可。
- **头发和裙子会动**：走动、转身时长发的发梢会被甩出去再弹回来，平时也轻轻飘；走路时裙摆跟着步子摆，坐下时整条裙子前倾、搭在腿上。
- **和现实同步**：窗外的天色跟着电脑时钟走（清晨/白天/黄昏/夜晚），墙上的钟是准的；天气默认自己变化，也可以接真实天气（见下）。

## 你可以做什么

- 拖动旋转镜头；滚轮（触控板两指上下滑）往鼠标指着的地方缩放，想看哪个角落就把鼠标放在那儿往前滚；右键拖动（触控板两指按下拖动）或按住 Shift 拖动是平移。看乱了按「镜头复位」。
- 点地板：她走过去。点家具：她去用（床、窗、电脑、书架、懒人垫、盆栽、小球、台灯、电饭煲、洗碗盆、小音箱、红缨枪）。点她：摸摸头。
- 底部按钮：指定她做某件事（包括练枪、打拳、放歌、拍照）、切换时间和天气、开关台灯、开关声音、镜头跟随。

## 角色模型

房间里的她有两种外观：

- **内置的**：用代码拿几何体搭的 Q 版，比较粗糙，什么都不放时用它。
- **你放进来的模型**：把「图生 3D」工具（混元 3D、Tripo 等）生成的 **带贴图的 GLB** 放进 `public/models/`，刷新页面就会换上。文件夹里有多个 `.glb` 时用最新的那个；想固定用某一个，在 `config.json` 的 `character.model` 里写文件名，写 `"off"` 则强制用内置的。

放进来的模型**原样使用，不减面、不压贴图**。它不需要带骨骼：加载时会自动对齐到内置角色的身高，按内置骨架的关节位置给每个顶点算权重，之后走、坐、躺、转头这些动作直接驱动它。

生成模型时的建议：

- 用「多张图片」模式，上传正面、侧面、背面三张（`模型素材/用你的三视图切的/` 里有切好的）。
- 面数选最高档，要带贴图，导出 GLB。
- 手臂自然下垂的图生成出来最好动；手举在胸前的图，手臂会和身体连在一起，手部动作会受限。

表情是另外叠在脸上的一层：眼睛睁着时用的是模型自己画好的眼睛，眨眼、闭眼、换嘴型时才盖上去。它需要知道这个模型的眼睛和嘴在哪，写在同名 `.rig.json` 的 `face` 里（现在这个模型已经配好）；换了新模型而没配 `face`，就没有眨眼和表情。

对位不准时，可以在模型旁边放一个同名的 `.rig.json` 微调（比如 `abc.glb` 配 `abc.rig.json`），能调的参数和默认值都列在 `public/src/model.js` 的 `RIG_DEFAULTS` 里。调试时在网址后面加 `?rig` 会显示骨骼位置，加 `?model=off` 临时换回内置角色，加 `?dev` 会加载调试工具（快进、摆镜头、连拍，用法写在 `public/src/devtools.js` 开头）。

## 和 QQ 同步

在 `config.json` 的 `onebot` 一段填上 NapCat 的正向 WebSocket 地址（比如 `ws://127.0.0.1:3001`）、`accessToken`、她的 QQ 号 `botQQ`、你的 QQ 号 `ownerQQ`，把 `enabled` 改成 `true`。NapCat 在同一台机器上跑着的话，启动房间服务后顶部会显示「QQ 已连接」。

- 房间服务是作为**第二个客户端**连到 NapCat 的 WebSocket 上，和 DSH 的 dsh-onebot 互不影响。平时只读（`get_login_info`、`get_friend_msg_history`）；唯一会发出去的是她在房间里拍的照片（`send_private_msg`，只发给 `ownerQQ`；`config.json` 的 `photo.sendToQQ` 设成 `false` 就只存本地）。
- 你发消息 → 手机在哪儿就在哪儿亮起来，她停下手头的事，过去拿起来看（睡着的话会被吵醒、揉眼睛坐起来）。
- 你发了 B 站视频 → 聊完她去电脑上看它。
- 她回复 → 那句话从她头顶冒出来，表情和小动作跟着语气走。
- 她的回复里说了要做什么（「我去窗边看看」「晚安我先睡了」「跳个舞给你看」）→ 聊完真的去做。你让她去做而她没拒绝，也会去做。
- 戳一戳她 → 会吓一跳。
- 只显示 `ownerQQ` 里的号和她的私聊；群消息和别人的私聊不上屏（`showOthers` 可改）。

为什么她的回复有一两秒延迟：NapCat 的 `reportSelfMessage` 是 `false`（默认）时，她自己发出去的消息不会被推送，所以房间服务在有来信后每 1.5 秒查一次聊天历史把它补上。不需要改 NapCat 的配置。

**她看完消息才回你。** 她的 AI 收到你的消息一般两三秒就写好了回复，比房间里的她跑去拿手机快得多。所以 QQ 插件在发她的回复和表情包之前，先问房间服务 `GET /api/read-wait`：她有没有拿到手机、把你的消息看完。看完了才发出去，最多等 25 秒；房间没开或者服务没跑，就直接发。这一步要改 QQ 插件，见「和 DSH 及其他插件结合」。另外，聊天时 `/api/state` 里多了 `before`，是手机响之前她在干什么，你问「在干嘛」时她答得上来。

### 让她的意识直接控制身体

除了「从聊天内容里听出她想干什么」，她的 AI 本体也可以直接看到、指挥这个身体：

```bash
curl -s http://127.0.0.1:5177/api/state
```

```bash
curl -s --max-time 110 -X POST http://127.0.0.1:5177/api/act -H 'content-type: application/json' -d '{"action":"photo","target":"window","wait":true}'
```

**`"wait":true` 是为了让她先做完再回你。** 不带它时，接口把指令转给房间页面就立刻返回，这时候身体才刚开始走。她拿到 `ok` 就回「拍了，收到没？」，照片其实要过半分钟才拍出来。带上它，接口会一直等到页面报告「做完了」才返回，最多等 100 秒（`timeout` 可调，最长 300 秒）。DSH 的 bash 工具超过 120 秒会把命令转到后台、让她先往下走，所以默认值留在这之下。

- 先看消息再动手：你发来消息、她的 AI 马上下了指令时，身体不会半路扭头去做。她会先跑去拿起手机，把你的消息看完、点点头，再放下手机去做。跑一趟就完的事（关音响、开灯、浇花、跳舞、拍照……）做完还会回去拿起手机，拿到了才算「做完了」。这时她的 AI 才发出回复，房间里她正好拿着手机在打字。所以一条带 `wait` 的指令一般要等十几秒到一分钟。
- 「做完」怎么算：一次性的事（拍照、浇花、跳舞、开灯、放歌……）是真做完了，拍照是照片已经发出去；要待一阵的事（看窗外、玩电脑、看书、躺着、睡觉、吃饭……）是已经待下了：坐上窗台、钻进被窝、坐下开吃。
- 返回里有 `done`（做完没有）、`doing`（她现在在干什么）。拍照还有 `photo.taken` / `photo.sentToQQ` / `photo.file`，放歌有 `music`。没做完会带上 `timeout` 超时、`cancelled` 被打断或 `error`。
- 不带 `wait` 时返回里会有 `"done":false` 和一句提醒，告诉她身体还没做完。
- 她亲自指挥身体以后，她紧接着回你的那句话会边做边说，不再把正在做的事打断。她回复里的「拍了」「我在窗边」也不会再被当成新指令重做一遍，等你下一条消息进来才恢复。`node room.mjs do …` 默认就带着 `wait`。

完整说明写在 [给鲸鲸的说明.md](给鲸鲸的说明.md) 里，是直接写给她看的。她的工作区说明里有了这些内容，她就知道自己有身体了：主人问「在干嘛」时可以先看一眼再答，想做什么也可以主动去做。

把它（或者它的精简版）放进她 AI 的工作区说明里（DSH 是工作区的 `AGENTS.md`），记得写上 `wait` 的用法，她就知道怎么用这个身体了。

  然后在那个终端里直接打字就是「你发消息」，`/r 内容` 是「她回复」，`/poke` 是戳一戳。

## 和 DSH 及其他插件结合

这个仓库只有房间本身。她的「脑子」（会聊天的 AI）、QQ 账号这些都在外面，本仓库不包含它们的代码。整体是这样接起来的：

```
QQ ⇄ NapCat（OneBot 11 正向 WebSocket）
        ├─ DSH 的 QQ 插件（dsh-onebot-qq）：她的 AI 在这儿收消息、回消息
        └─ 房间服务 server.mjs：第二个客户端，平时只读聊天记录，拍照时发图
她的 AI ──（shell 里 curl）──→ 房间服务 /api/state、/api/act：看自己在干嘛、指挥身体
房间页面 ⇄ 房间服务（推送 + 上报状态）
```

1. **NapCat**：开一个正向 WebSocket 服务端（比如 `ws://127.0.0.1:3001`，设好 token）。DSH 的 QQ 插件和房间服务都连它，互不影响。别的 OneBot 11 实现（LLOneBot、Lagrange 等）理论上也行，没试过。
2. **DSH**：她的 AI 要能执行 shell 命令（用 `curl` 调房间接口）。把 [给鲸鲸的说明.md](给鲸鲸的说明.md) 的内容（或者精简版）放进她工作区的 `AGENTS.md`，她就知道自己有个身体、怎么看、怎么指挥。只做到这一步，房间就已经能跟着聊天动起来了。
3. **（可选）先看完消息再回**：要在 QQ 插件里加一小段。插件把她写好的回复发出去之前，先请求：

   ```
   GET http://127.0.0.1:5177/api/read-wait?timeout=25
   ```

   房间页面开着时，这个请求会一直挂着，直到房间里的她拿到手机、把你的消息看完（或者超时）才返回 `{ "ready": true/false, "waited": 秒数, "doing": "她在干嘛" }`；房间页面没开时立刻返回 `{ "ready": true, "roomOpen": false }`。插件拿到返回（不管 `ready` 是什么）或者请求失败（服务没开），都照常发出去，所以加上它不会让回复丢掉，最多晚 25 秒。
4. **（可选）心里话**：她写成「（独白：……）」的话不会发到 QQ，房间也就看不到。想让它在房间里冒成云朵气泡，让她的 AI 同时调用一次 `{"action":"think","text":"……"}`（写法在 [给鲸鲸的说明.md](给鲸鲸的说明.md) 里）。
5. **B 站视频**：聊天里出现 B 站链接或分享卡片时，房间服务自己去查 B 站的公开接口拿标题和封面，不经过她的 AI。

不用 DSH 也行：任何能发 HTTP 请求的 AI 或脚本都能用 `/api/state`、`/api/act` 控制她，接口清单见 `GET /api/actions` 或 `node room.mjs actions`。
